# 上港科技项目验收合规 Demo

这是一个面向客户演示的虚构样本工程，用于展示科技创新项目验收材料的基础合规审核能力。项目不包含客户真实材料、真实签章、真实编号或真实人员信息。

## 启动

```bash
npm install
npm run dev
```

默认地址：

- 前端：`http://localhost:5173`
- 后端：`http://localhost:8787`

生产构建：

```bash
npm run build
npm run start
```

## Docker 部署

仓库已提供 `Dockerfile`，线上平台建议选择 Dockerfile 构建，不要在构建脚本里执行 `npm update -g npm`。

```bash
docker build -t sipg-acceptance-demo .
docker run -p 8787:8787 --env-file .env sipg-acceptance-demo
```

如部署平台需要填写端口，使用 `8787`；如平台自动注入 `PORT`，服务会读取平台提供的端口。

## 演示材料文件

工程内置两套样本，但输入页只展示当前送审材料；二次提交样本仅在结果页用于生成对比：

- `materials/issue-demo`：当前客户送审材料，输入页展示为 15 份正文材料和若干附件。
- `materials/fixed-demo`：模拟整改后的二次提交材料，只在对比页按需解析展示。

每个材料包下还有 `source-files` 目录，模拟真实交付时的多文件输入。前端和接口对外只暴露 `.pdf`、`.docx`、`.xlsx` 展示名：

- 立项文件、封面、测试报告等展示为 PDF。
- 任务书、申请书、工作报告、研究报告等展示为 Word。
- 指标、经费、用户数据和结构化抽取结果展示为 Excel。

如修改了 `server/data/samplePackets.js`，可重新导出：

```bash
node scripts/export-materials.mjs
```

后端接口会优先从 `materials/<packet>` 的独立文件解析材料包，再执行规则审核。前端入口支持展开每个样例包，逐个勾选正文材料、表格附件、结构化快照和解析文本；未勾选的文件不会进入本次解析，因此可演示“缺材料/少附件/补齐后复核”的完整流程。

## AI 复核

后端支持 DashScope OpenAI-compatible 接口，读取本地 `.env`：

```bash
cp .env.example .env
```

然后在 `.env` 中填入真实的 `DASHSCOPE_API_KEY`。

接口：

- `GET /api/sample-packets`：返回样例包及其可选文件清单。
- `POST /api/parse-sample`：按所选样例文件重新解析材料包并执行审核。
- `POST /api/parse-uploaded`：按用户上传的文件重新解析材料包并执行审核。
- `POST /api/ai-review`：基于解析后的材料包和规则发现生成 AI 复核意见。
- `GET /api/health`：返回 `dashscope_configured` 状态。

前端不会自动调用 AI。用户在总览页点击“生成 AI 复核意见”后才会调用 DashScope，并按当前材料包和所选文件集合缓存结果。

## 演示内容

内置项目为“港区智能闸口作业协同与异常预警系统”，定位为系统类科技创新项目。材料包固定为 15 页：

1. 批准立项文件摘录
2. 计划任务书关键页
3. 验收材料封面
4. 验收文件清单
5. 科技项目评审申请书
6. 工作报告
7. 研究报告目录与摘要
8. 系统架构与数据流
9. 关键功能与技术指标完成情况
10. 产品测试/检测报告
11. 项目成果用户使用报告
12. 效益分析
13. 项目经费决算报告
14. 成果、知识产权与固定资产清单
15. 附件证据清单

## 样例包

- 当前客户送审材料：模拟客户首次送审材料，系统预审后会发现项目名称不一致、负责人不一致、清单与正文冲突、缺申请单位意见、缺测试签章、用户报告疑似研发方代拟、缺用户使用报告盖章、缺财务章、测试指标缺具体数值、效益分析缺计算过程、附件证据缺失、经费研发支出口径缺失等问题。
- 模拟二次提交材料：模拟同一项目补充材料后的再次送审，权威字段、签章、指标闭环、经费表和附件证据已补齐，但系统仍按未知状态重新解析，仅保留知识产权、固定资产和财务真实性等人工复核项。

## 审核能力

当前版本使用确定性规则审核，便于无客户数据时稳定演示：

- 总览视图：按高/中/低/人工复核分组，给出整改优先级和第一条高风险跳转。
- 材料视图：逐页展示解析来源、抽取字段、表格内容、审核发现和整改建议。
- 对比视图：展示第一次提交与再次提交的预审差异。
- 多文档抽取：从模拟三项计划发文、计划任务书、验收正文和附件证据清单中抽取字段与指标。
- 材料齐套：系统类项目必须提供批准立项文件、任务书、工作报告、研究报告、测试报告、用户使用报告、效益分析、经费决算、成果清单等。
- 字段一致：项目编号、项目名称、承担单位、项目负责人、执行期与权威字段比对。
- 形式签章：申请单位意见、测试组长签章、应用单位盖章、财务章等。
- 内容质量：测试结果是否有具体数值和样本量，任务书指标是否逐项闭环，用户使用报告是否来自实际应用单位，效益分析是否有计算过程，报告结构是否完整。
- 附件证据：检查使用说明、测试原始记录、系统截图、预算调整审批、软著受理通知等附件是否支撑正文。
- 人工复核：知识产权证明、固定资产原件、财务真实性等需要人工确认。

## 客户沟通口径

第一阶段 demo 展示的是“提前发现高频退回问题”的基础审核台，不做正式财务审计，也不判断研究成果真实性。后续如果客户能提供脱敏样本或正式规则口径，可扩展为真实文件上传、OCR、Word/PDF 解析、规则配置后台和审核报告导出。
