# 上港科技项目验收合规审核：知识库、记忆、Skill 与 Agent 能力规划

## 1. 规划目标

本项目不是单纯做一个“材料检查页面”，而是要把科技项目验收合规审核拆成可持续运营的数字员工能力：

- 知识库负责沉淀制度、规则、模板、历史案例等相对稳定的事实依据。
- 记忆负责沉淀某个项目、某次审核、某轮沟通中的上下文和判断过程。
- Skill 负责沉淀可复用的审核方法、抽取方法、整改方法和输出模板。
- Agent 负责在具体任务中调度知识库、记忆、Skill、文件解析、规则引擎和人工确认。

这四类能力需要分层设计，不能混用。否则产品会出现两个问题：一是材料越审越多但经验没有沉淀；二是每次审核都像重新开始，无法解释为什么给出某个判断。

## 2. 四类能力边界

| 能力 | 业务定义 | 输入来源 | 沉淀位置 | 更新机制 | 在本 Demo 中的体现 |
| --- | --- | --- | --- | --- | --- |
| 知识库 | 可被多项目复用的制度、标准、模板、行业知识和历史退回案例 | 验收管理办法、材料清单模板、客户规则口径、历史退回原因、系统类项目要求 | 企业级知识资产库、部门知识库、项目模板库 | 管理员维护、规则版本发布、人工审核后入库 | 内置验收规则、系统类项目必交材料、字段一致性规则 |
| 记忆 | 单个项目或单次任务过程中的上下文、决策、用户确认和处理状态 | 上传材料、权威字段、解析结果、审核发现、用户修正、二次提交对比 | 项目记忆、审核任务记忆、用户偏好记忆 | 每次任务结束自动生成快照，用户确认后固化 | 当前提交/二次提交状态、解析结果、审核发现、对比视图 |
| Skill | 可复用的标准作业方法，不是单条知识，而是一套可执行步骤 | 人工审核 SOP、反复纠错过程、稳定的审核流程、最佳实践模板 | 个人 Skill、团队 Skill、企业 Skill | 从任务中抽取，人工确认发布，使用反馈持续优化 | 材料齐套性审核、字段一致性核验、签章检查、整改建议生成 |
| Agent | 执行任务的数字员工，负责计划、路由、调用工具、执行规则、请求确认和输出结果 | 用户目标、材料文件、知识库、记忆、Skill、外部系统 | Agent 工作区、任务运行记录、审计日志 | 按任务运行，不直接替代知识库或 Skill 沉淀 | 文件解析、规则预审、AI 复核、整改对比、风险摘要 |

## 3. 业务层面的输入与沉淀设计

### 3.1 知识库：沉淀“审核依据”

知识库应沉淀相对稳定、可跨项目复用的内容：

- 科技项目验收制度、管理办法、项目验收流程。
- 各类材料模板：封面、申请书、工作报告、研究报告、测试报告、用户使用报告、经费决算报告。
- 系统类项目专项要求：测试报告、上线使用证明、用户使用数据、系统说明书、知识产权、固定资产清单。
- 客户内部口径：哪些章必须盖、哪些字段以任务书为准、哪些附件可替代、哪些问题必须退回。
- 历史退回案例：退回原因、整改方式、最终通过材料样式。

产品设计上，知识库不应该由普通用户在审核过程中随意污染。推荐流程是：用户在审核中提出规则补充或人工判断后，进入“待确认知识”，由项目管理员或业务负责人审核后发布为正式知识版本。

### 3.2 记忆：沉淀“当前项目为什么这样判断”

记忆应沉淀任务过程，而不是替代知识库：

- 项目级记忆：项目名称、编号、承担单位、负责人、执行期、任务书指标、历史审核轮次。
- 任务级记忆：本次上传了哪些文件、系统识别了哪些材料、哪些字段冲突、哪些问题已确认。
- 话题级记忆：用户曾经确认“该附件可以替代测试原始记录”“该章允许后补”等过程性判断。
- 用户偏好记忆：客户经理/审核人员对输出格式、风险表达、会议汇报口径的偏好。

在验收合规业务中，记忆最重要的价值是“可恢复现场”和“可解释”。二次提交时系统不应只重新审核一遍，还要知道第一轮指出过什么、客户补了什么、哪些问题仍未关闭。

### 3.3 Skill：沉淀“怎么审、怎么改、怎么输出”

Skill 应沉淀可重复执行的工作方法，例如：

- 验收材料齐套性预审 Skill：识别项目类型，匹配必交材料，输出缺失清单。
- 权威字段一致性核验 Skill：以立项文件/任务书为权威源，核对封面、申请书、报告正文和经费表。
- 系统类项目附件审核 Skill：检查测试报告、上线截图、用户使用数据、系统说明书、知识产权和固定资产证据链。
- 经费决算表核验 Skill：检查预算口径、决算金额、研发支出科目、财务章和调整审批。
- 整改回复生成 Skill：按问题严重程度生成整改建议、补材料清单和对客户沟通话术。
- 复审对比 Skill：比较首次提交与二次提交，判断问题是否关闭。

Skill 的沉淀路径建议分三级：个人 Skill 先服务个人审核效率，团队 Skill 经复用验证后共享给项目组，企业 Skill 经业务负责人确认后纳入标准能力。

### 3.4 Agent：执行“端到端审核任务”

Agent 不是单个提示词，而是一个可审计的任务执行者。产品中建议使用以下 Agent 能力：

- Plan Mode：先展示审核计划和材料识别结果，用户确认后再执行正式预审。
- Semi-Auto：高风险判断、规则新增、材料替代关系必须人工确认。
- 工具调用：调用文件解析、表格抽取、规则引擎、知识库检索、AI 复核、报告导出。
- Hooks/事件触发：客户上传新材料后自动触发预审；二次提交后自动触发复审对比。
- Connector Packs：后续接入 OA、项目管理系统、档案系统、财务系统、电子签章系统。
- Audit Trail：记录每一步解析、规则命中、人工确认、AI 建议和最终输出，满足内控追溯。

## 4. 与验收合规业务的能力匹配

| 业务环节 | 用户动作 | Agent 能力 | 知识库作用 | 记忆作用 | Skill 作用 | 输出 |
| --- | --- | --- | --- | --- | --- | --- |
| 材料接收 | 上传 Word/PDF/Excel 材料 | 文件识别、分类、去重 | 提供材料类型定义 | 记录本次提交文件集合 | 材料归类 Skill | 材料清单、缺失提示 |
| 权威字段建立 | 识别立项文件、任务书 | 字段抽取、权威源判断 | 提供权威字段优先级 | 记录项目权威字段 | 权威字段核验 Skill | 项目基准信息 |
| 初次预审 | 点击提交预审 | 规则编排、风险分级 | 提供验收规则 | 记录命中问题和原因 | 齐套/一致/签章/内容 Skill | 预审问题清单 |
| 人工确认 | 审核人员确认或修正 | Semi-Auto 人工介入 | 规则可进入待发布区 | 记录确认结果 | 纠错转 Skill 候选 | 确认后的审核结果 |
| 整改建议 | 生成补充材料要求 | AI 复核、建议生成 | 检索历史退回案例 | 结合当前问题状态 | 整改回复 Skill | 整改清单、沟通话术 |
| 二次提交 | 上传补正材料 | 自动复审、差异对比 | 沿用同一规则版本 | 关联上一轮问题 | 复审对比 Skill | 问题关闭情况 |
| 归档复盘 | 项目完成后归档 | 自动总结、沉淀候选 | 新增案例入库 | 固化项目全过程 | 抽取可复用 Skill | 项目审计记录、经验沉淀 |

## 5. 产品设计建议

### 第一阶段：演示版

目标是让客户看懂流程和价值，不追求真实系统集成。

- 使用内置样例和上传入口展示材料接收、AI 解析、规则预审、原文预览、问题定位、二次提交对比。
- 知识库先以固定规则和样例口径体现。
- 记忆先体现在“当前提交”和“二次提交”的审核状态保存。
- Skill 先以固定审核模块体现，不开放配置。
- Agent 能力重点展示解析步骤、等待状态、风险归因和整改建议。

### 第二阶段：试点版

目标是接入客户真实脱敏材料，验证规则准确率。

- 建立客户专属验收知识库：制度、模板、规则口径、历史退回案例。
- 增加项目记忆：每个项目保留上传记录、审核轮次、人工确认和整改闭环。
- 将高频流程沉淀为可配置 Skill：齐套性审核、字段一致性、经费检查、附件证据链。
- 引入人工确认机制：规则变更、材料替代、高风险判断必须留痕。

### 第三阶段：生产版

目标是成为客户科技项目验收内控流程的一部分。

- 接入项目管理、档案、OA、财务、电子签章等系统。
- 建立企业级 Skill 库，按部门、岗位、项目类型授权调用。
- 支持定时巡检和事件触发：材料到达自动预审，临近验收自动提醒，二次提交自动复核。
- 输出标准审核报告、整改通知、管理看板和审计追踪。

## 6. 对客户的表达口径

这个方案不是把所有文档简单丢给大模型，而是把验收审核拆成四层能力：

- 知识库保证审核依据统一。
- 记忆保证项目上下文不丢失。
- Skill 保证高频审核动作可复用。
- Agent 保证端到端流程可执行、可介入、可追溯。

因此，系统的价值不只是“这次帮你找出几个问题”，而是随着项目数量增加，客户自己的验收规则、退回经验、整改模板和审核 SOP 会持续沉淀，逐步形成面向科技项目验收的专属数字员工。
